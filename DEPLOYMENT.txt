1. CONNECT THE SUBDOMAIN

In your Vercel project, Settings > Domains, add checkout.nexool.shop.
Copy the exact DNS record Vercel displays for this project.
In Namecheap > Domain List > nexool.shop > Manage > Advanced DNS:
  Type: CNAME Record (if this is the record Vercel requests)
  Host: checkout
  Value: the exact target supplied by Vercel, without https://
  TTL: Automatic
Replace conflicting records for ONLY the checkout host if necessary.
Leave the root domain and www records pointing to Shopify.
If Namecheap is not hosting your nameservers, edit the record at your actual
DNS provider instead. Wait for Vercel to show valid configuration and HTTPS.
https://vercel.com/docs/domains/working-with-domains/add-a-domain

2. FINISH THE SHOPIFY APP

Use a merchant-owned app installed on bfuwye-df.myshopify.com, with the app
and store owned by the same Shopify organization. This pilot uses the
client-credentials grant, not the OAuth install flow needed for other merchants.

Grant these Admin API scopes:
  read_products,read_inventory,read_markets,write_orders,write_draft_orders,read_fulfillments

read_fulfillments is needed to subscribe to fulfillments/create and
fulfillments/update for automatic tracking. read_orders can read an order's
tracking details but does not by itself authorize these webhook subscriptions.
Release a new app version and approve this added permission on the store.
Test connections refreshes the Shopify token and reports this permission check.

write_draft_orders is essential: the application asks Shopify to calculate
shipping, discounts and taxes, reserves a draft, then completes that same
draft after verified payment. Write scopes imply their corresponding read
scope. Publish/release your updated app version and approve the changed
permissions on the store installation. Set the app's webhook API version to
2026-07. Ensure the app has the customer-data access needed for addresses,
email and order data; a successful token alone does not establish that access.

Save the app's Client ID and Client Secret privately in Vercel (step 4).
The code refreshes its Shopify access token automatically.
Shopify API version is pinned to 2026-07; review supported versions before
July 2027 and update/test rather than depending on automatic fall-forward.

3. PREPARE WHOP AND A DATABASE

Whop:
- Open the business dashboard for biz_huT0pZAGlTYetE.
- Ensure the account is approved/configured for the actual physical goods
  you sell. Create/select the product that will represent Nexool purchases;
  copy its prod_ ID into WHOP_PRODUCT_ID.
- Create a server API key with access to this business and the operations
  used here: account read, payment quotes, payments create/read, and inline
  one-time plan creation. For tracking, also allow shipments create/update.
  Dashboard permission labels can vary; use the corresponding capabilities.
- Product sync defaults to Off: checkout uses the configured Whop product and
  WHOP_RECEIPT_TITLE. Turn it On in /setup and import the active Shopify catalog
  to create persistent product mappings. A single-product cart uses its mapped
  Whop product once ready; mixed carts retain one whole-cart payment with item
  names in its description. Shopify preserves every original variant/quantity.
- Verify buyer-added fees are disabled and tax treatment matches Shopify.
  The application compares Whop's quoted total, currency AND tax against
  Shopify and refuses payment if they differ. Do not remove this check to
  force an order through. Mixed tax categories under one Whop product may
  require further integration work and are not a supported assumption.
- Start with USD. Enable other currencies only after confirming your Whop
  account supports them and testing each market. This code never silently
  converts an unsupported currency to USD.
- Apple Pay/Google Pay availability depends on Whop, the account, eligible
  devices/browsers and domain verification. DNS alone does not activate them.
  Complete any domain/wallet setup Whop requires for checkout.nexool.shop
  and verify wallets on actual supported devices before advertising them.

Database:
- Create a PostgreSQL database, for example Neon through Vercel Marketplace
  or your Neon account. Choose a region near the Vercel application region.
- Copy its pooled PostgreSQL connection string, including TLS/sslmode=require,
  into DATABASE_URL. Do not use a read-only database user.
- Persistent database storage is required: Vercel's local files are not used
  to store orders. The /setup page will create the tables.

6. CONNECT WEBHOOKS

Whop business developer/API settings > Webhooks:
  URL: https://checkout.nexool.shop/api/webhooks/whop
  Event: payment.succeeded
  Payload/API date: 2026-10-07-1 (the code expects account_id)
Use the current v1 event envelope compatible with this API date, not a legacy
v2 business_id payload. Save the endpoint's signing secret exactly as given
as WHOP_WEBHOOK_SECRET, then redeploy.
Verify Whop can reach the production endpoint. Deployment Protection must
not intercept customer checkout or webhook requests with a Vercel login.

Shopify tracking:
In /setup click Register Shopify tracking webhooks after APP_URL points to
the final domain. It creates app-owned FULFILLMENTS_CREATE and
FULFILLMENTS_UPDATE subscriptions at /api/webhooks/shopify, reusing matching
subscriptions if already registered. Do not substitute manually-created
Shopify admin notification webhooks with a different signing secret.
Set TRACKING_SYNC_ENABLED=true and redeploy when ready to test tracking.

Verified Whop events are persisted before acknowledgement. The application
re-fetches the payment and checks merchant, session, quote, amount, currency
and refund state before completing the reserved Shopify order. Daily Vercel
cron retries pending sync; /setup also has Retry order / tracking sync.
Cron is a backup, not a high-volume queue. At scale, replace it with a durable
worker and monitoring. Do not rely on a single daily batch for a public SaaS.

7. ADD THE SHOPIFY CART HANDOFF

Test in a duplicate, unpublished theme first.
Shopify > Online Store > Themes > duplicate your theme > Edit code.
Create snippets/nexool-checkout.liquid and paste the supplied file from
the shopify folder. In layout/theme.liquid, just before </body>, add:

  {% render 'nexool-checkout' %}

The snippet ships with const enabled = false. Keep the live theme disabled
until the test below passes. For your private theme preview, change it to
true after enabling payments for your controlled test.

It intercepts standard cart form Checkout buttons, including the Tidal cart
page. It saves quantity changes, reads Shopify's cart, and passes only variant
IDs, quantities and locale to this app. Prices are re-fetched server-side.
Shopify's selected market country starts the checkout; the shipping country
recalculates the final prices/currency. This is not automatic IP geolocation.
If needed, configure Shopify's market/country selector separately.

Cart drawers, third-party cart widgets, and dynamic Buy Now/Shop Pay buttons
need theme-specific integration. Until verified, use the normal full cart
page for this checkout. Do not remove the regular checkout fallback.
Gift cards, subscriptions, custom line properties and cart notes/attributes
fall back to Shopify. Complex bundles and checkout extensions are not
supported by this pilot. The original Shopify cart is not cleared after an
external purchase; customers should not submit the same bag again.

8. CONTROLLED LIVE TEST, THEN LAUNCH

No live order has been placed or charged by this code's author. Browser
preview tests do not establish provider/account compatibility.
After checking Whop's fees/tax and credentials, set:
  PAYMENT_SETTINGS_VERIFIED=true
  CHECKOUT_ENABLED=true
Redeploy. Keep the public theme bridge disabled while testing privately.

Use a low-value product you own and a payment method you are authorized to
use. This package uses production Whop endpoints; do NOT assume a test card
or sandbox mode is supported. /preview never charges or calls the providers.

Check all of these before directing customer traffic:
- Correct product, variant and quantities; unavailable inventory is blocked.
- Shipping-country prices/currency equal the configured Shopify market.
- Applicable shipping rates, discounts and tax equal your intended order.
- Whop checkout total and actual buyer charge match, without added fees.
- Successful payment produces exactly one PAID Shopify order with original
  variant IDs, address and email. Refresh/replay does not duplicate it.
- Declined payment does not create a paid Shopify order.
- Shopify order-confirmation email arrives using your store's notification
  settings. Verify this live: draft-order notifications and custom apps may
  differ from the Online Store channel, and Whop may also send a receipt.
- Confirmation page links to Shopify's real order-status page.
- Apple Pay and Google Pay work on eligible devices, if available.
- CJ recognizes the paid Shopify order, fulfills it, and writes tracking to
  Shopify; the webhook then creates/updates Whop shipment tracking.
- Repeat for every currency/market you intend to enable.

When this passes, enable the bridge in the published theme. To roll back,
set its enabled constant to false and set CHECKOUT_ENABLED=false/redeploy.
Existing payment webhooks and synchronization still run when checkout is
disabled, so already-paid orders can finish.

WHAT IS AND IS NOT INCLUDED

Included: responsive, unbranded checkout UI, market-contextual product prices, address
and delivery selection, discount input, Whop hosted payment fields, signed
webhooks, duplicate-payment/order safeguards, private setup/status screen,
Shopify order-status link, optional single-parcel tracking synchronization.

This does not customize Shopify's hosted checkout or require Shopify Plus
for checkout UI extensions. It is a separate checkout application creating
Shopify orders via Admin API; it is not a Shopify-approved payment gateway.
Platform/account eligibility and any applicable fees must be verified for
your own store before launch.

It cannot reproduce the native Shopify checkout thank-you page. Customers
see this app's confirmation and can open Shopify's order-status page.
No guaranteed conversion uplift is claimed; measure real funnel results.

Not yet included: recurring subscriptions, multi-store OAuth/dashboard,
public SaaS onboarding/compliance webhooks, per-product Whop mappings,
automatic refunds/cancellations/dispute synchronization, multi-parcel Whop
tracking, Shopify checkout extensions, gift cards, B2B, duties/import-tax
parity, or every discount/bundle/customer-specific pricing scenario.
No separate CJ API integration: connect CJ to Shopify, map the variants,
fund/approve CJ fulfillment, and configure CJ to return Shopify tracking.
Orders created by this app need to be eligible for your CJ sync settings.

OPERATIONS

Review /setup after launch. needs_review and payment_unknown require
checking Whop BEFORE asking a customer to pay again. A request timeout may
still mean a payment succeeded. Never blindly create a replacement charge.
Complete/refund disputed or failed orders manually in both systems as needed.
Multiple shipment numbers appear as an issue for manual Whop review.
Tracking reconciliation covers recent orders for 55 days; webhook processing
still supports later fulfillment events while records remain stored.
Abandoned unpaid sessions are cleaned after seven days where safe; ambiguous
payments and completed orders remain for reconciliation. Set a customer-data
retention policy, restrict database access and enable backups before launch.
Avoid analytics that record session URLs or customer addresses.
